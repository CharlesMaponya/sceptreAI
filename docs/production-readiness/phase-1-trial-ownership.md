# Phase 1 trial ownership implementation contract

Status: **in progress; fixed/local/accelerator/clustering CV and standalone Tune are integrated; recovery, grants and Train remain open**. This contract preserves P1-W02, P1-W08, P1-W19 and the multi-trial loss test; it is not a readiness waiver. The existing `TrainingTrial`, `WorkflowAttempt`, `WorkflowEvent` and checkpoint tables should carry the work.

## Current execution paths

The production RayJob builder sets `TRAINING_EXECUTION_MODE=ray` and `AUTOML_MODEL_PODS=1`. Candidate dispatch therefore reserves a complete Ray worker for each candidate. `candidate_runtime._execute` changes the mode to `candidate` before fitting. The CPU Tune branch in `_fit_candidate` requires mode `ray`, so the default candidate-worker path needs local search. It now uses an explicit deterministic search loop with durable trials. Unfenced local legacy execution still uses `BayesSearchCV`. GPU-selected local search also uses the deterministic durable loop. CPU fallback evaluates under distinct cpu-fallback trial identities bound to the source accelerator; it does not overwrite GPU trial receipts. Enabling nested Tune inside these tasks would make trials wait for CPUs already reserved by their parent candidate.

`training/tune_runtime.py` supports standalone Tune CV trials and has a real local two-trial smoke test. Standalone Tune now enrolls each suggestion before dispatch and appends a physical Ray trial-ID event. Its worker receives explicit parent context and uses the same immutable trial contract and lease. The initial audit found no production `TrainingTrial` creation path. `services/training_trials.py` now provides transactional enrollment with parent fencing, immutable suggestion parameters, idempotent identity and bounded superseded-parent replacement. Worker lifecycle helpers now also enforce a 90-second renewable child lease and publish immutable terminal evidence transactionally. The fixed-parameter CPU CV branch now calls them through `training/trial_runtime.py`. The default local CPU search branch is integrated. Clustering parameter sweeps also use the adapter, including models evaluated through `fit_predict`. Fold preprocessing is lazy and begins under the first committed trial lease; replay uses stored fold metrics. Supervised GPU-selected CV/search also call the adapter. GPU and CPU-fallback evaluations have distinct identities, with source accelerator recorded in the fallback contract. These paths have CPU-estimator simulation coverage; actual GPU hardware remains unqualified. Training launch does create `TrainingCandidate` rows. The reconciler supersedes active child trials and creates pending replacement rows. Enrollment now binds the first submission identity only to an untouched pending replacement whose predecessor, parent, generation, workload and trial lineage match. Competing identical bindings converge; changed execution identities are rejected. Exhausted child generation budgets stop the parent replacement. Pending children are cancelled and started children fail, with logical trial status updated.

## Required changes

The verified CV/search/clustering/Tune integrations do not close the full execution and recovery inventory below. Leased worker start/heartbeat and immutable terminal-result/event helpers now support fixed-parameter CV, local parameter search, clustering sweeps and standalone Tune workers. The adapter commits before computation, renews a child lease, and returns committed success/failure on replay. Final full-data model fitting remains outside this CV trial. Explicit predecessor CV result adoption now verifies terminal receipts and lineage. Signed attempt grants, full recovery, object-checkpoint authorization and production Train integration remain required. The updated training entrypoint now claims a worker owner and renewable 90-second parent lease, with a heartbeat every 15 seconds. Competing owners, expired leases and cancelled-run admission are rejected. Shared progress/result and worker failure writes reject expired leases; an already-committed result remains recoverable through its existing receipt/fence/CAS. Legacy parents without leases remain compatible outside this entrypoint. The observer now queues expired-parent cancellation and bounded replacement atomically, after recovering any committed result. Cancellation verifies the exact fence/scope before deleting in the recorded namespace. Current local code passed a fresh suspended-RayJob deletion/replay/neighbor-preservation check on k3d; real worker death and current-image qualification remain open. Signed grants and complete worker qualification remain required.

1. Enroll every search suggestion before CV starts, including local CPU/GPU search, fixed-parameter supervised CV, clustering parameter sweeps and Tune dispatch. Record accelerator fallback as a new owned execution rather than an invisible nested retry. Replace the opaque local search call with an explicit suggestion/evaluation loop using the existing deterministic searcher, retaining estimator configuration, preprocessing, scoring, seed, iteration count and resource limits. Keep standalone test behavior separate from production: a production run must not silently continue without its durable candidate/attempt context.
2. Bind the candidate, suggestion and canonical parameters to a logical `TrainingTrial`. Bind each execution to a typed child `WorkflowAttempt` with the same project/run and its exact parent run generation. Store the Ray/Tune identity when applicable. Persist this intent before dispatch. Concurrent duplicate enrollment must return the same identity; conflicting parameters or lineage must fail.
3. Guard worker start, heartbeat, result publication and failure with the child fence and current parent generation. Use the existing transition functions. Match parent-before-run lock ordering used by replacement, then lock child records consistently. A replacement must supersede all active old trial attempts in one transaction before admitting new work. The worker must reject expired grants and disallowed predecessor checkpoints.
4. Commit canonical result evidence and terminal CAS together. Repeated acknowledgement loss must not duplicate results or terminal events. Reuse a predecessor result only through its verified digest and explicit allowlist; do not invent a new suggestion or overwrite completed evidence to bypass conflicts. Use the existing event/checkpoint mechanisms instead of a second trial database.
5. Give recovery to the durable reconciler. Keep Ray task, Tune and Kubernetes retries disabled; represent replacements with append-only attempt generations and bounded budgets. Preserve ordinary model failure behavior while propagating stale ownership and unresolved external side effects. Trial failures, cancellations and exhausted recovery need durable reasons and the existing authorized replay mechanism.
6. Integrate the production Ray Train path under the same ownership contract before claiming Train qualification. A validation script using Train is not a production implementation.

## Required verification

- Run the default whole-candidate search and standalone Tune with real PostgreSQL; inspect trial and attempt rows, identities and terminal evidence for each actual suggestion.
- Exercise concurrent same/conflicting enrollment and lost database commit acknowledgements. Replay enroll/start/result/failure commands twice.
- Run a parent with multiple active trials, supersede it transactionally, and prove that every old worker rejects publication while the replacement preserves logical trial history.
- Exercise lease/grant expiry, wrong project/run/candidate/parent fences, conflicting terminal results and rejected predecessor checkpoints.
- Preserve deterministic search evidence, candidate resource limits, GPU fallback semantics and ordinary model failures. Avoid nested CPU reservation deadlocks.
- Qualify process loss at enrollment, dispatch, identity persistence, checkpoint and terminal commit boundaries on the current deployed image. Local mocks and the existing two-trial smoke test do not close these gates.

The 45 GB migration rehearsal, current-image deployment and recovery of seven missing historical QA objects remain separate unresolved requirements.

Tune dispatch records are committed before a configuration is returned to Ray. Lost dispatch acknowledgements can replay that enrollment and event; workers generate a fresh owner identity before claiming the lease. A fresh Tune invocation can redispatch completed logical suggestions and read their receipts. This is same-parent result replay, not durable process-loss recovery or verified checkpoint adoption. Search checkpoints preserve algorithm state while retaining the caller's current execution context; a new parent still cannot adopt completed trial receipts implicitly. Parent fence tokens are excluded from suggestion configurations and the searcher's JSON checkpoint. The explicit worker context is carried through Ray's parameter handoff.

Completed CV results and ordinary failures can now be adopted by a replacement parent. The reconciler records exact typed database receipt references in `predecessor_checkpoint_allowlist`, alongside existing object checkpoint URIs. A result reference binds the source attempt, logical trial and result digest; it grants no object-store access. Enrollment verifies the source's terminal event type, payload digest, terminal CAS, parameter identity and parent lineage before committing a new adoption event and terminal receipt. It preserves source history and consumes no new worker claim or CV execution. Generation budgets still apply.

If a replacement dies before adoption, the reconciler carries only verified receipt authorizations forward. Adoption requires an uninterrupted sequence of superseded parents with matching scope, workload and consecutive generations, and the exact authorization at every skipped generation. Missing or altered authorization fails closed. This database result mechanism does not authorize predecessor object reads or qualify signed grants, native process-loss recovery, final fitting or artifact side effects.

A pod-bound admission API is now available as the issuer-authentication prerequisite. It verifies TokenReview, exact attempt/fence audience, current scope and physical pod/controller lineage, with bounded expiry and digest-only credential evidence. Native k3d verifies a real pod-bound token and negative cases using an unscheduled pod. Ray manifests now project these proofs and configured training startup/trial execution/renewal consume admission with proof-capped leases. Splitter/preparation now consume admission and enforce owned, proof-capped leases with stale publication/failure guards. Dataset expiry now queues durable old-generation cancellation plus bounded replacement; retired submission replay cannot recreate jobs. New non-Ray analysis launches now consume admission and leases and publish report/receipt/CAS atomically through ModelRun-bound attempts; analysis RunKind and logical keys distinguish them from model searches. Managed batch expiry/loss now queues exact UID-scoped cleanup and fresh-generation replacement through the outbox; report commits are preserved. First-delivery pending CPU legacy analysis now has a deferred, absence-checked tracked handoff and worker protocol guard. Retried/running/ambiguous legacy migration, cleanup of inconsistent profiles, separate signed child grants, provider delegation and deployed process-loss/rotation/TLS qualification remain open.
